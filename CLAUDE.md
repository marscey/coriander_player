## Project Overview

Coriander Player is a cross-platform music player built with Flutter (Dart) and Rust, using Material Design 3 / Material You theming. It supports local music playback and WebDAV cloud streaming. Forked from [Ferry-200/coriander_player](https://github.com/Ferry-200/coriander_player), with added WebDAV and macOS support.

**Targets**: Windows, macOS, iOS, Android, Linux

## Architecture

### Layer Structure

```
lib/
├── main.dart                  # App entry: init Rust, MediaKit, hotkeys, tray, window
├── entry.dart                 # MaterialApp + GoRouter config, Provider setup
├── play_service/              # Core playback service layer
│   ├── play_service.dart      # Singleton owning PlaybackService, LyricService, DesktopLyricService
│   ├── playback_service.dart  # Actual playback control
│   ├── engine/                # Player engine abstraction
│   │   ├── player_engine.dart # Abstract PlayerEngine interface
│   │   ├── bass_engine.dart   # Desktop: BASS native library via FFI
│   │   └── media_kit_engine.dart  # Cross-platform fallback via media_kit
│   ├── lyric_service.dart     # Lyric loading & sync
│   └── desktop_lyric_service.dart  # Desktop floating lyric window control
├── library/                   # Audio library data model (Audio, Artist, Album, Playlist)
├── cloud_service/             # WebDAV cloud integration
├── metadata/                  # Metadata scraping (MusicBrainz, Chinese scrapers, orchestrator)
├── lyric/                     # Lyric parsers: LRC, KRC, QRC formats
├── page/                      # Page-level widgets by feature
├── component/                 # Reusable UI widgets
├── src/bass/                  # Dart FFI bindings for BASS audio library
├── src/rust/                  # Auto-generated flutter_rust_bridge bindings (DO NOT EDIT)
└── platform_helper.dart       # Cross-platform path & detection utilities
```

### Key Architectural Patterns

**Player Engine Abstraction**: Abstract `PlayerEngine` (`lib/play_service/engine/player_engine.dart`) with two implementations:
- `BassPlayerEngine` — desktop-only, wraps BASS native library via FFI
- `MediaKitPlayerEngine` — cross-platform fallback using `media_kit`
- `PlayerEngineFactory` selects engine based on platform and user settings
- `PlatformDependencyManager` manages engine availability per platform

**State Management**: Provider + ChangeNotifier. Key providers: `ThemeProvider`, `CloudServiceManager`, `AppSettings`, `PlayService`.

**Routing**: `go_router` with `StatefulShellRoute.indexedStack` for tab navigation. `AppShell` adapts layout (mobile bottom nav vs. desktop side nav) via `ResponsiveBuilder`. Route paths defined in `lib/app_paths.dart`.

**Rust FFI Bridge**: `flutter_rust_bridge` v2.12.0 auto-generates Dart bindings from `rust/src/api/**/*.rs` → `lib/src/rust/`. Rust modules: `tag_reader` (audio tags via `lofty`), `system_theme`, `smtc_flutter` (Windows media controls), `installed_font`, `logger`, `utils`.

**Service Singletons**: `PlayService.instance`, `AppSettings.instance`, `AppPreference.instance`, `CloudCacheManager.instance`, `PlatformDependencyManager.instance`, `ScraperOrchestrator.instance`, `RecentPlayService.instance`.

### Platform-Specific Notes

- **BASS library** (desktop only): Native audio libs must be present in `windows/bass/` or `macos/bass/`. CMake/build scripts copy them to the app bundle automatically.
- **WASAPI**: Windows-only audio output API. macOS/Linux do not need `basswasapi` files.
- **`lib/src/rust/`**: Auto-generated by `flutter_rust_bridge`. Never edit these files manually — modify `rust/src/api/` and regenerate.
- **`desktop_lyric`**: Separate Flutter app ([repo](https://github.com/marscey/desktop_lyric.git)), built independently and placed in the app bundle's `desktop_lyric/` directory. Build scripts support `--build-mode release|debug` and `--install-to-app` options.

## Testing

Two parallel test systems for mobile:

### Flutter Integration Tests

**Location**: `integration_test/` (must be in project root, Flutter hardcodes this path)

**Key constraint**: All tests must be in a single `testWidgets` block because `flutter_rust_bridge` can only initialize once.

**Run commands**:
```bash
# Build for iOS simulator first (required for mobile tests)
flutter build ios --simulator

# Run specific test
flutter test integration_test/mobile_ui_test.dart

# Run all integration tests
flutter test integration_test/
```

**Test files**:
- `mobile_ui_test.dart` — Mobile UI adaptation (10 scenarios)
- `webdav_cloud_test.dart` — WebDAV cloud service (6 scenarios)
- `ios_media_control_test.dart` — iOS media controls
- `metadata_store_test.dart` — Metadata persistence
- `scraper_test.dart` — Metadata scraping

### Maestro Tests

**Location**: `test/maestro/` (YAML declarative tests)

**Setup**:
```bash
# Install Maestro CLI
brew tap mobile-dev-inc/tap
brew install mobile-dev-inc/tap/maestro

# Build and install app to simulator
flutter build ios --simulator
xcrun simctl install booted build/ios/iphonesimulator/Runner.app
```

**Run commands**:
```bash
# Run single flow
maestro test test/maestro/flow.yaml

# Run all flows
maestro test test/maestro/

# Generate JUnit report
maestro test test/maestro/flow.yaml --format JUNIT --output report.xml
```

**Test flows**:
- `flow.yaml` — Main test flow (9 scenarios: launch, navigation, UI verification)
- `smoke_test.yaml` — Quick smoke test
- `nav_test.yaml` — Navigation switching test

### Testing Strategy

- **Daily development**: Use Maestro for quick validation
- **Precise UI assertions**: Use Flutter integration tests (can check Widget types, properties)
- **CI pipeline**: Run both (Maestro for smoke, Flutter for deep verification)

### Common Testing Issues

- **Maestro "Unable to launch app"**: App not installed to simulator. Run `flutter build ios --simulator` then `xcrun simctl install booted build/ios/iphonesimulator/Runner.app`
- **Flutter `_pendingFrame == null`**: Multiple `app.main()` calls cause state leak. Solution: merge all tests into single `testWidgets`
- **Maestro can't find Chinese text**: Ensure simulator language is Chinese, or use `id` selectors instead of text matching

## Important Conventions

- The project UI is primarily in **Chinese** (simplified). All user-facing strings are in Chinese.
- Audio formats supported: mp3, flac, aac, m4a, wav, ogg, opus, ape, wv, dsf, dff, mid, amr, ac3, wma, asf, aif, aiff, mpc, mp2, mp1.
- Lyric formats: LRC (line), KRC (Kugou character-by-character), QRC (QQ Music enhanced).
- `shared_preferences` and `sqflite` for local persistence. `flutter_secure_storage` for credentials.
- `pinyin` package used for Chinese character sorting in artist/album lists.

## Development Workflow

### Adding New Features

1. **UI Changes**: Modify files in `lib/page/` or `lib/component/`
2. **Playback Features**: Extend `lib/play_service/` (add new engine or modify existing)
3. **Lyric Formats**: Add parser in `lib/lyric/` following existing LRC/KRC/QRC patterns
4. **Cloud Service**: Extend `lib/cloud_service/` for new cloud providers
5. **Rust Integration**: Add new modules in `rust/src/api/`, then regenerate bindings

### Regenerating Rust Bindings

After modifying Rust code in `rust/src/api/`:
```bash
# The bindings are auto-generated during build
flutter run  # or flutter build
```

The `flutter_rust_bridge` package automatically regenerates `lib/src/rust/` from Rust source.

### BASS Library Setup (Desktop)

**Windows**:
1. Download BASS libraries from [un4seen.com](https://www.un4seen.com/bass.html)
2. Place 64-bit DLLs in `windows/bass/`: `bass.dll`, `bassape.dll`, `bassdsd.dll`, `bassflac.dll`, `bassmidi.dll`, `bassopus.dll`, `basswv.dll`, `basswasapi.dll`
3. CMake automatically copies them to app bundle during build

**macOS**:
1. Download macOS BASS libraries
2. Place in `macos/bass/`: `libbass.dylib`, `libbassape.dylib`, `libbassdsd.dylib`, `libbassflac.dylib`, `libbassmidi.dylib`, `libbassopus.dylib`, `libbasswv.dylib`
3. Build script automatically copies and signs them

**Note**: WASAPI is Windows-only. macOS/Linux don't need `basswasapi` files.

## Common Development Tasks

### Adding a New Player Engine

1. Create new file in `lib/play_service/engine/` (e.g., `new_engine.dart`)
2. Implement `PlayerEngine` abstract class from `player_engine.dart`
3. Register in `PlayerEngineFactory` in `player_engine.dart`
4. Update `PlatformDependencyManager` if platform-specific

### Adding a New Lyric Parser

1. Create parser in `lib/lyric/` following `lrc_parser.dart` pattern
2. Add format detection in `lyric_service.dart`
3. Update lyric format list in this document

### Modifying UI Components

1. Reusable widgets go in `lib/component/`
2. Page-level widgets in `lib/page/`
3. Use Provider for state management (access via `context.read<T>()` or `context.watch<T>()`)
4. Follow Material Design 3 / Material You theming patterns

### Debugging Playback Issues

1. Check `PlayService.instance` state
2. Verify BASS library presence (desktop) or media_kit setup (mobile)
3. Check `PlatformDependencyManager` for engine availability
4. Review logs in `lib/src/rust/` (Rust logger module)
